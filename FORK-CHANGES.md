# bandzalkin/band-sdk-python fork changes

Commit-pinned fork of [band-ai/band-sdk-python](https://github.com/band-ai/band-sdk-python)
consumed by [band-ai/band-agent](https://github.com/band-ai/band-agent) as its `band-sdk`
dependency. It carries upstream pull requests that band-agent needs before upstream merges
and releases them, so band-agent never monkeypatches the SDK.

## Branches and tags

| Ref | Content |
| --- | --- |
| `main` | Mirrors upstream `main`. Never commit here. |
| `band-agent-patches` (default) | Upstream `main` plus the fork-only commits below, kept as a linear history. |
| `band-agent-patches-latest` | Generated by the replay: the fork-only commits replayed onto the newest upstream `main`. Never commit here. |
| `staged/<date>-<sha>` tags | Every revision the replay staged, validated by upstream's gate. |

band-agent pins only a staged revision, by its full commit SHA, in its `pyproject.toml` and
`uv.lock`; it never follows a branch. Both branches are force-pushed, so the `staged/` tag is
what keeps a pinned commit fetchable after the branches move on. To pin a change made on
`band-agent-patches`, run the replay; it stages and tags that revision.

## Patch set

Each upstream pull request is one squashed commit whose message ends with an
`Upstream-PR: band-ai/band-sdk-python#N` trailer. The replay reads that trailer.

| PR | Change | Applied over |

| [#731](https://github.com/band-ai/band-sdk-python/pull/731) | A busy ACP session is backpressure: the turn retries against the same session or is deferred, never torn down as a provider failure. | upstream `main` with #754 merged: the busy-retry loop builds the emitter without the retired mention argument, and the busy-recovery tests reply through the Band tool (`FakeACPAgent.reply`), or assert the closing thought when no Band tool is injected. |
| [#730](https://github.com/band-ai/band-sdk-python/pull/730) | A retry-exhausted failed `/next` head no longer starves later deliveries: recovery drains one complete, ordered actionable snapshot. | #753: a locally skipped head hands the drain to the snapshot, so #753's re-offer guard is a backstop and its wedge tests expect one `/next` poll. The sync point still accepts #753's no-progress result, but only once the message is terminal. |
| [#713](https://github.com/band-ai/band-sdk-python/pull/713) | A room the platform stopped is adopted as stopped instead of re-posting events into 403s. | upstream `main`: a newer detached-turn test models a running room explicitly. |
| [#760](https://github.com/band-ai/band-sdk-python/pull/760) | A message claim the platform refuses because the room is stopped adopts the stop instead of running the turn; `ExecutionContext.claim_message` gives hosts claiming into a running turn the same handling. | #713, and #730: the fork's stale recovery already drains one actionable snapshot that ends once the room is stopped, so #760's sweep and sync guards are dropped and its stale-claim test feeds that snapshot. The last fork-only commit adds this file and the replay workflow. It has no trailer and is
always replayed.

`CHANGELOG.md` is not part of the patch set. Release Please rewrites its head on every
upstream release, so carrying entries there would break the weekly replay for no benefit.

## Weekly upstream replay

`.github/workflows/band-agent-replay.yml` runs every Monday at 06:17 UTC and on demand. It:

1. Takes every commit on `band-agent-patches` that upstream `main` does not contain.
2. Skips a commit whose `Upstream-PR` is merged upstream: upstream now carries that change.
3. Cherry-picks the rest, in order, onto the newest upstream `main`.
4. Runs upstream's gate (pre-commit hooks and the full test suite) on the result.
5. Force-updates `band-agent-patches-latest` only when the replayed tree differs from it.

The run summary lists the PRs it skipped as merged and those closed upstream without merging.

band-agent's `fork-freshness` workflow runs at 07:30 UTC on Mondays. It files a band-agent
issue when this replay is not green or when `band-agent-patches-latest` differs from the
commit band-agent pins.

A red run means upstream moved under a patch. Nothing is pushed; band-agent stays on its pin
until someone resolves the replay by hand.

It is the only workflow enabled in this fork's Actions. Every upstream workflow (CI, E2E,
release, publishing) is disabled in the repository settings: the fork never releases, and
the replay runs upstream's gate itself. Re-disable any workflow upstream adds later with
`gh workflow disable <file> -R bandzalkin/band-sdk-python`.

## Procedures

Set up a clone once:

```sh
git clone https://github.com/bandzalkin/band-sdk-python.git
cd band-sdk-python
git remote add upstream https://github.com/band-ai/band-sdk-python.git
git fetch upstream
```

### Sync `main` with upstream

```sh
gh repo sync bandzalkin/band-sdk-python --branch main
```

### Add an upstream pull request

```sh
git checkout band-agent-patches
git fetch upstream pull/<N>/head
git merge --squash FETCH_HEAD     # resolve conflicts, run the affected tests
git restore --source=HEAD --staged --worktree CHANGELOG.md   # if the PR touched it
git commit -m "<PR title>" -m "Squashed from https://github.com/band-ai/band-sdk-python/pull/<N> at <sha>." \
  -m "Upstream-PR: band-ai/band-sdk-python#<N>"
git push origin band-agent-patches
gh workflow run band-agent-replay.yml -R bandzalkin/band-sdk-python
```

Add a row to the patch-set table, naming any conflict resolution.

### Refresh a pull request that gained commits upstream

Rebuild the branch at the same position: `git rebase -i upstream/main`, mark the PR's commit
`edit`, then `git reset --hard HEAD~1`, repeat the squash from "Add an upstream pull
request", and `git rebase --continue`. Push with `--force-with-lease`.

### Drop a pull request upstream merged

The replay already skips it. To drop it from the default branch as well, rebase the branch
onto upstream:

```sh
git checkout band-agent-patches
git fetch upstream
git rebase upstream/main   # drop the merged PR's commit when it stops or comes up empty
uv run --all-packages pytest
git push --force-with-lease origin band-agent-patches
```

Remove its row from the patch-set table. When the patch set is empty, band-agent can return
to an upstream commit or release, and this fork can be archived.

### Resolve a red replay

1. Open the failed run and note the upstream target and the commit that stopped applying.
2. Rebase `band-agent-patches` onto `upstream/main` locally and resolve that commit.
3. Run `uv run --all-packages pre-commit run --all-files` and `uv run --all-packages pytest`.
4. Push `band-agent-patches` with `--force-with-lease` and re-run the replay workflow.

### Move band-agent to a new revision

In band-agent, set the `band-sdk` commit in `pyproject.toml` to the newest `staged/` tag's
commit (the `band-agent-patches-latest` head), run `uv lock --upgrade-package band-sdk`, and
run band-agent's full CI gate.
